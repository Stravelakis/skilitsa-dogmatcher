## What DogMatcher is

A quiz for a **WordPress** website. A visitor answers questions about their life (how active they are, whether they have children, how long the dog would be home alone) on a scale of 1 to 5. The quiz then compares those answers with every dog breed in your data and shows the **three best matches** (gold, silver, bronze), each with a short reason. More breeds are listed below, and each result has its own link you can share.

It is built for [skilitsa.com](https://skilitsa.com), so the quiz texts and the original data are **in Greek**. The admin screens are in English. You can use your own sheet in another language (see "Your Google Sheet").

It is **two plugins**:

- **Skilitsa Core** holds your data and does the scoring. It adds the **Skilitsa** menu to your admin. Visitors never see it.
- **Skilitsa Matcher** is the quiz visitors use. It needs Core.

> **Watch out** There is no ready-to-install download yet. No release is published on GitHub as of 21 Nov 2026, and the plugin folders need a one-off preparation step (see "Install it"). Plan on a developer or hosting helper for that step. After it, everything else is done in the WordPress admin.

This page describes version **2.0.0**.

## What you need

- A WordPress site, version 6.4 or newer, on PHP 8.1 or newer.
- A **Google Sheet** with eight tabs (below), shared as "anyone with the link can view".
- A **Breed post** for each breed. This is the part people miss: the quiz scores only breeds that exist as posts under **Skilitsa → Breed posts**. The data in your sheet is attached to a breed by matching the post's address name (its **slug**) to the sheet's `breed_key`.
- Optional: an account with an AI provider, only if you want the AI draft helper.

## Install it

1. **Get the two plugin folders ready.** Each folder needs a small loader file that is not in the repository, generated by a developer tool (Composer). Ask your developer to run the repository's `bin/build-release.sh`, which makes two upload-ready zips (`build/skilitsa-core.zip` and `build/skilitsa-matcher.zip`), or to run `composer install --no-dev --optimize-autoloader` in each plugin folder. Without it you will see a red notice in your admin: "Skilitsa Core: dependencies are missing."
2. In WordPress go to **Plugins → Add New → Upload Plugin** and upload the Core zip, or copy the finished folders into `wp-content/plugins/`.
3. **Activate Skilitsa Core first, then Skilitsa Matcher.** If you activate Matcher alone you will see a notice that it needs Core 2.0.0 or newer.
4. A **Skilitsa** menu appears in the admin sidebar, and **Settings** appears beside the Deactivate link on the Plugins page.

> **Do this first** Before anything else, open **Skilitsa → Settings** and paste **your own** sheet address into **Source sheet**. Out of the box the plugin points at the sheet it was built with. Importing from that sheet is harmless but is not your data.

## Your Google Sheet

The sheet needs eight tabs with these exact names:

`SETTINGS`, `UI_TEXTS`, `SECTIONS`, `TRAITS`, `QUESTIONS`, `MAPPING`, `RESULT_TEMPLATES`, `BREEDS`.

In plain words:

- **TRAITS** lists the things a dog can be like (the default sheet has 24: energy, barking, shedding, and so on).
- **QUESTIONS** lists what the visitor is asked (the default sheet has 30).
- **MAPPING** says which question tells you about which trait, and whether the answer is flipped (a "yes, barking bothers me a lot" answer means the dog should be quiet).
- **BREEDS** gives each breed a 1 to 5 value for each trait (the default sheet has 257 breeds).
- **UI_TEXTS** and **RESULT_TEMPLATES** hold all the wording visitors read.

To make a version in another language, copy the sheet, translate the text columns, and keep every tab and column name exactly as it is. The importer looks for them by name.

The two numbers that say how much a mismatch matters for each trait (the **penalties**) are **not** in the sheet. They come from built-in defaults, and you can change them on the **Traits** screen.

## Bring the data in

1. Go to **Skilitsa → Import**.
2. Press **Fetch and preview**. The plugin reads your sheet and shows a table (**Table**, **Now**, **After**, **Change**) of what would change, with any warnings. Nothing is saved yet.
3. If the preview shows errors (**This import will not run.**), there is no apply button. Fix the sheet (a missing tab, a missing column) and fetch again. Warnings do not stop you.
4. Press **Apply this import**. A green **Import applied.** box lists what was written. It is all-or-nothing: if anything fails, nothing is changed. If nothing would change, there is no button.

> **Watch out** Trait values are attached **only to breeds that already have a published Breed post** with a matching slug. A breed in your sheet that has no matching post is skipped quietly. After importing, check **Skilitsa → Breed data**: it lists every breed with a post and how many traits it has. If your breed list looks short, the posts are what is missing.

Importing again later **replaces** the breed values, questions and wording with whatever is in the sheet. The only things that survive are trait rows you edited by hand on the **Traits** screen. So make your changes in the **sheet**, and import again, rather than editing values on the Breed data screen: those edits are overwritten by the next import.

## Put the quiz on a page

Edit a page and either add the **Skilitsa matcher** block (search "Skilitsa" in the block inserter), or type this on its own line:

```
[skilitsa_matcher]
```

Only one quiz block fits on a page. Visitors who have JavaScript turned off see a short message that the quiz needs it.

## What a visitor sees

1. One question at a time, with a progress bar. Each has five choices from the low end to the high end of the scale.
2. A **terms checkbox** (a short "this is informational, not professional advice" line). The visitor must tick it before **Next** works.
3. On most questions, two optional buttons: one that means "I definitely want this" (the **dealbreaker**) and one that means "it makes no difference to me" (**ignore**). In the default Greek sheet they read **Το θέλω οπωσδήποτε** and **Δεν μου κάνει διαφορά**.
4. At the end, the **podium**: three breeds with medals, a score, and an open-and-close explanation each (it works from the keyboard). More breeds follow in a row you can scroll.
5. Breeds that a dealbreaker ruled out are in a closed list below, with the trait that excluded them. If nothing survives, the page suggests which answer to relax.
6. If the top three are very close (within 5 points by default), a note above the podium says they all fit about equally. The podium is still shown.
7. If the visitor has answered too little, no breeds are shown, only a message asking for a few more answers.

Each result has its own link, `/match/<12 random characters>/`. Opening it later shows the result as it was first worked out, even if you have changed your data since.

## How the match is decided

You do not have to follow the maths, but you should know the rules:

- Each answer says what the visitor wants for one or more **traits**. Questions can matter more or less (the weight is in your sheet).
- For each breed, every trait is compared. A mismatch costs more in one direction than the other. A visitor who wants a quiet dog is not bothered by a quiet dog, but is by a loud one. That is why two numbers exist per trait.
- A **dealbreaker** does two things: it counts that trait double, and it **removes** a breed that misses it by too much (a gap of 2 points of cost or more by default).
- A trait the visitor cannot be disappointed on is left out of the comparison.
- If the quiz knows only a little about the visitor, scores are pulled toward 50 so they do not look too sure. With fewer than **8** traits known, no breeds are shown at all.
- **Same answers, same data, same result.** Nothing is random, and ties are broken the same way every time (lower mismatch first, then by breed name). Only the chosen wording of an explanation varies, and it is fixed per breed.

## The admin screens

| Screen | What it is for |
|---|---|
| **Settings** | The engine knobs, each with its default beside it and one sentence of help, plus the accent colour, the question flow and the source sheet. |
| **Traits** | The two penalty numbers and the weight for each trait. Rows you change stay as you left them through later imports. |
| **Breed data** | Every breed that has a post, and which traits it is missing. |
| **Breed posts** | The breed pages themselves (title, text, picture). |
| **Import** | Fetch the sheet, see the changes, apply. |
| **AI drafts** | Suggestions from the optional AI helper, waiting for you to approve or reject. |

> **Watch out** On the Settings screen, **Cards on the podium** and **Further suggestions** currently do nothing: the podium is always 3 breeds and the list below shows 7. Also, of the three **Question flow** choices, only "Core questions first, the rest after" changes anything today: it shows only the core questions. These two points are in the project notes as known problems.

## Privacy

- **The visitor's browser talks only to your own website.** It does not call Google or any other outside service. The quiz does not load outside fonts or scripts.
- **What your site keeps for each quiz run:** a random result code, the answers with their "definitely" and "no difference" marks, the result, the time, and a few click events. The plugin does **not** record an IP address, a browser identifier or any user account. (Your web host's own server logs are separate and not controlled by the plugin.)
- **Deleted after 90 days.** A daily job removes older results. It relies on WordPress's scheduled tasks running.
- **Result links are not secret, just unguessable.** Anyone who has the link can open that result. Result pages tell search engines not to list them and tell caches not to keep them.
- **What your server sends out:** it fetches your Google Sheet when you use Import, and it contacts an AI company only if you set one up and run a task.
- **To keep a visitor's reading size:** the quiz can read a text-size preference stored in the visitor's browser. It does not write one.

## Optional AI drafts

Off until you set it up, and **admin-only**. It can suggest breed trait values, check the data for contradictions, help with translation and draft picture descriptions. Each suggestion lands in **Skilitsa → AI drafts**. **Approve** applies it through the normal form; **Reject** changes nothing. No AI-written word reaches a visitor on its own.

To turn it on, your developer adds three lines to your site's `wp-config.php`:

```php
define( 'SKILITSA_AI_BASE_URL', 'https://your-provider.example/v1' );
define( 'SKILITSA_AI_MODEL',    'your-model' );
define( 'SKILITSA_AI_KEY',      'your-key' );
```

The key goes only in `wp-config.php`, never in the admin, because a key stored in the database is copied into every backup. The full notes, with provider examples, are in [docs/ai-configuration.md](https://github.com/Stravelakis/skilitsa-dogmatcher/blob/HEAD/docs/ai-configuration.md). Always check model names with your provider first: a wrong name just fails, it does not give a wrong answer.

## If something is wrong

<details>
<summary>A red notice says "dependencies are missing"</summary>

The plugin's loader file was not generated. Ask your developer to run the build step in "Install it", then reactivate.
</details>

<details>
<summary>Matcher says it needs Skilitsa Core</summary>

Core is not installed, not active, or older than 2.0.0. Activate Core first.
</details>

<details>
<summary>The quiz box is empty, or says the quiz is not set up</summary>

There are no questions in your data yet. Run **Skilitsa → Import**. If the box is empty with no message, check that the page really has the block or `[skilitsa_matcher]`.
</details>

<details>
<summary>Import shows errors and no apply button</summary>

Read the red lines. Usual causes: the sheet is not shared with "anyone with the link", a tab name is spelled differently, or a required column is missing.
</details>

<details>
<summary>The result page says it cannot be found</summary>

The link is wrong, or the result is older than 90 days and was deleted. If every result link fails on a new install, open **Settings → Permalinks** in WordPress and press **Save**, which refreshes the address rules.
</details>

<details>
<summary>Breeds are missing from the results</summary>

Check **Breed data**. A breed with no post, or whose post slug does not match the sheet's `breed_key`, has no data.
</details>

<details>
<summary>Everyone sees a "too many requests" message</summary>

The quiz allows 60 requests a minute per visitor address. If many people share one address (for example behind a proxy that hides it), they can hit that limit together.
</details>
